# Component reference

The 19 public names documented below are exported by [index.ts](../../src/components/scientific/index.ts) and registered for MDX. React authors import from `src/components/scientific`. See the compiled [gallery source](examples/gallery.mdx). Internal helpers are not part of this public map. This reference was checked against source on 14 November 2026; inspect code before extending an API.

## Source and API boundaries

- [core.tsx](../../src/components/scientific/core.tsx): Figure and Sidenote.
- [interactions.tsx](../../src/components/scientific/interactions.tsx): Term, LinkedEquation, LinkedTerm, LinkedMark, PredictReveal and Stepper.
- [projection.tsx](../../src/components/scientific/projection.tsx), [model-experiments.tsx](../../src/components/scientific/model-experiments.tsx) and [week1-diagrams.tsx](../../src/components/scientific/week1-diagrams.tsx): specialised Week 1 figures.
- [pilot.tsx](../../src/components/scientific/pilot.tsx): Week 2 SVDExplanation and NoiseExperiment.

Props below are the actual TypeScript contracts, not a proposed design. There are no universal `data`, `fallback`, `onChange`, `className` or `id` overrides on the specialised no-prop figures. Avoid wrapping one in another Figure: it already owns its caption/ID, except SVDExplanation, which is a linked explanation rather than a Figure.

`ProjectionExplorer` (no props) is the Week 1 visualisation. Use `<ProjectionExplorer />` once per page (fixed ID `projection-experiment`). It rotates an orthonormal basis around (2,1), reveals the complementary projection, and provides a calibration preset for y=(2,3) projected onto span(1,2). It exposes a labelled keyboard/touch range, reveal/reset buttons, numerical live summary, accessible SSR SVG and a no-JavaScript explanation. Pure calculations live in `projection-math.ts`; the real 2D view does not purport to prove the complex n-dimensional theorem. Preset numbers are exact analytically; displayed numbers are rounded to three decimals. Subsequent angle changes update both geometry and prose.

Expression-valued MDX props (including PredictReveal choices and explanation) are now enabled for trusted repository content. Do not use this compiler for untrusted content. This closes a limitation discovered during direct Week 1 MDX authoring.

## Week 1 explanatory figures

These specialised components take **no props** and are registered for MDX. Use each at most once per page because it owns a stable ID. All have semantic captions and labelled, server-rendered SVG. Static sequences remain server components; only the two button-based experiments add client state. The gallery compiles every example below.

Pure real 2D arithmetic is in `week1-math.ts`, separate from rendering. It is teaching-specific, not a public general-purpose numerical library. `diagram-primitives.tsx` provides internal panels and a fixed-scale coordinate plane; it is not registered as a universal MDX diagram API. All essential explanations are visible without hover or JavaScript. No animation or automatic playback is used. Static diagrams have no tab stops; control groups use ordinary button navigation, not tab-widget arrow-key semantics.

Example of custom linking:

```mdx
<LinkedEquation>

<LinkedTerm term="variance">σ²</LinkedTerm>

<LinkedMark term="variance">Variance measures mean squared deviation.</LinkedMark>

</LinkedEquation>
```

For mathematical blocks use `$$...$$`; inline `$...$`. The explicit button API avoids dependence on generated KaTeX markup. `\\htmlClass` is allowed for author styling but does not automatically register interactive symbols. Citations are explicit links and reference lists; GFM footnotes have backlinks. There is no BibTeX processor or automatic figure numbering in this version.

## Behaviour that must not be inferred from component names

- **Term**: opens on pointer hover, focus or click/tap; Escape, blur or pointer exit closes. It is not a click-to-toggle popover and offers no placement/collision API. The tooltip is hidden in the no-JavaScript initial state; repeat essential definitions in prose. Its inline button does not automatically receive the 44px minimum used by `.sci-controls` buttons.
- **LinkedEquation**: a selection context, not a TeX renderer. `LinkedTerm` uses a semantic string ID; `LinkedMark` repeats it on a span. Selection remains active after pointer exit/blur until another term is selected or Escape clears it. Use a separate provider for unrelated groups. There is no automatic highlighting inside KaTeX or SVG; do not nest LinkedMark's HTML span inside an SVG.
- **PredictReveal**: starts with no choice. Reveal is disabled until selection; after reveal the fieldset is disabled until reset. `answer` must match one of the unique choice IDs; code does not validate malformed choices for the author. The explanation is a ReactNode and appears in noscript as well as after reveal. No scoring history or sketch capture exists.
- **Stepper**: starts at index zero, returns null for empty steps, disables navigation at each end and resets to the first step. Content occupies a shared grid to reserve the tallest panel; inactive panels are hidden/inert. Keep the step list stable during a mount. Use unique titles and IDs. The noscript branch repeats later content for reading; avoid fixed-ID figures inside steps without checking duplicate IDs in the rendered no-JavaScript document.
- **ProjectionExplorer**: angle −180° to 180° in 0.1° UI increments; initial vector (2,1), angle 0, second component concealed. Calibration sets (2,3), aligns the first ruler with (1,2), and reveals both components. Reset restores the original state. This is not a configurable basis editor.
- **NoiseExperiment**: σ₂ defaults to 0.2 (range 0.05–1), direction defaults to 45° (range 0–360°), noise length fixed at 0.1. Reset experiment resets these parameters; prediction and step controls have separate resets. No singular zero is selectable, although the pure calculation tests the pseudoinverse boundary.

Generic MDX usage appears in the gallery: Figure widths, Sidenote, Term, explicit LinkedEquation/LinkedTerm/LinkedMark, PredictReveal and Stepper. The fixed prediction in `_notes/es98a/week1.md` is an additional real prose-integrated example. There is no automatic prop forwarding to HTML or module-specific registration: new exports require the shared integration process.

Inside an MDX container, prefer ordinary Markdown paragraphs separated by blank lines. A multiline explicit `<p>` around MDX prose can generate another implicit paragraph inside it, causing invalid HTML and hydration failure. ReactNode props such as `explanation={<p>...</p>}` are JavaScript expressions and are a different context. The gallery is browser-checked so examples are validated beyond compilation.
