The source supplied ARCHER2 peak “28 PFLOPS (2020)”, £48M/four years, 25 GWh/year/~£6M, 85% node energy, 7,320 tonnes embodied CO2, +7,000 tonnes/year operational CO2, and clock-change ranges 74–95% performance / 80–93% energy. The notes retain the scientific questions and replace the clock example with the dated primary study. These undated accounting figures have not been independently confirmed for matching years/system boundaries and are not presented as current facts. Recover the original lecture references before restoring them as empirical evidence.

The original hardware-size/latency table and vector-extension dates also lacked a named CPU/toolchain. The revised course retains hierarchy levels and SIMD widths while treating those numbers as historical illustrations, not tuning constants. Generic smartphone teraFLOP/s and physical-node descriptions similarly need precision/platform context.

## Scope of confidence

The final review adds two explanatory derivations without changing the source computation: exact contiguous/cyclic triangular loads, and convergence of the two-buffer relaxation with fixed Dirichlet boundaries. The latter uses the maximum-norm bound `||G^m||∞ <= 1 - 5^-m` on an `m×m` interior. A positive-weight path from every point reaches the zero-error boundary within `m` steps; the remaining averaging weights have total at most `1 - 5^-m`. Periodic boundaries preserve constant error, so this proof cannot be transferred to them. This is an additional proof under explicit hypotheses, not a claim that the original racy in-place solver was correct. The new error-grid figure is checked by a pure immutable-field update and analytic contraction cases. Week 2's binary32 example uses ties-to-even and rounding after each addition; it does not assume arbitrary compiler reassociation.

Analytic models and selected native examples have explicit tests. This is not a formal verification of MPI implementations, OpenMP memory semantics or GPU kernels. CUDA lacks a local toolkit/device; its code has editorial/index/barrier review and pure indexing tests, not nvcc compilation or device execution. Source ML1–ML5 are empty and remain unavailable.
